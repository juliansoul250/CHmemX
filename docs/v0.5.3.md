# v0.5.3: fact identity and legacy corrections

[简体中文](zh-CN/v0.5.3.md)

This patch releases the identity and legacy-body fixes previously available on main.
The existing v0.5.2 tag is unchanged; installing that tag does not include these fixes.

- Exact identity and alias checks use all validated definitions, not a page of substring results. Display queries remain paginated; aliases still require review rather than automatic merging.
- A valid long historical record can receive a short correction. New uploads remain limited to 8192 characters; the existing legacy 512 KiB bound, conflict review, exact Owner confirmation and supersession history remain in force.
- Regression coverage includes project decision/evidence sources, complete correction/approval/recall flows, and large conflict responses through the standard MCP SDK across reconnects.

## Upgrade

Install the v0.5.3 package into the tool's existing or a separate verified environment, then reconnect that client's MCP process. Check the installed package and MCP handshake version; updating a source checkout alone does not update every client.

Preserve the current store path, policy, pending uploads and index configuration. Upgrading from v0.5.2 does not require store initialization or data migration; earlier releases and custom adapters need their own compatibility checks. Installation does not enable Personal mode, change approval policy, rebuild a user's index, or authorize new Active writes. Retain the old runtime for rollback until client verification is complete.

## Large responses

Legacy conflict responses contain the full current text and diff, so they can exceed 1 MiB. The SDK regression verifies complete data and stable request identity after reconnecting; JSON member order is not part of that contract.

This is not a guarantee that every desktop UI will display the whole response. There is no universal MCP 1 MiB output limit implied here. If a host truncates a result, use the complete CLI review and source artifacts before confirmation; an excerpt is not a complete review. No silent body truncation or new response format is introduced in this patch.

The empty-project source error-code wording and competitor comparisons are outside this patch.
