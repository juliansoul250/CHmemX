# v0.5.2 release notes

[简体中文](zh-CN/v0.5.2.md) · [Home](../README.md)

This patch fixes failed registration rollback, cross-project review side effects, source line-ending
comparison, and reconciliation of missing uploads. It does not change write policy or retrieval ranking.

## Registration and review

Project registration and source-key registration now use the canonical transaction boundary. A failed
operation restores its declared files and index entries when HEAD has not changed. Project directories
created by that attempt are removed only if empty. Unrelated files stay untouched. If another file
appears inside a new directory, `ROLLBACK_DIRECTORY_REMAINS` reports the retained path for inspection.
An already-existing project directory is rejected rather than adopted. A completed commit is not
undone merely because its command reply was interrupted.

Review checks the upload's project context before synchronizing its job or retiring a sealed batch.
Calling `review`, including `--refresh`, from another project returns `UPLOAD_CONTEXT_MISMATCH`
without invalidating the original confirmation. Global uploads remain reviewable from other contexts.

## Source validity

When a source's committed bytes still match, v3 also recognizes Git-declared CRLF/LF text conversion.
It checks committed and working attributes and Git's text classification without running clean,
smudge or other content filters. Actual content changes remain stale; binary data and conversions
requiring filters, `ident` or `working-tree-encoding` do not get this exception. Version-bound state
and evidence still require the original project revision.

The comparison follows [Git text and EOL attributes](https://git-scm.com/docs/gitattributes).
The exception requires `git check-attr --source` support; unavailable or unverifiable metadata fails
closed. No file, attributes or Git configuration is rewritten. Exact-byte matches retain their normal path.

## Missing uploads

Explicit `maintenance-plan --action reconcile` now consults the same bounded Git-history proof used
by status and review. A missing hot upload whose approval was reverted retains `COMMIT_NOT_CURRENT`
when that approval can be verified in current ancestry. Proof remains bound to its upload ID.
The receipt reports `payload_available=false`; lifecycle recovery does not reconstruct the lost body
or reactivate memory. Without proof, `UPLOAD_DATA_MISSING` remains the result.

## Upgrade and limits

Install the pinned package and restart its stdio process. Existing stores keep their policy, records
and indexes. Old dirty stores are not repaired automatically: inspect their exact registration diff
and HEAD before restoring any files. Regenerate unexecuted maintenance plans after upgrading.

The README now compares Team and Personal policies and separates current v3 retrieval from the
legacy `vector_memory.py` lexical pointer. Legacy commands and formats are retained. This patch
does not tune vectors, add a semantic model, shorten maintenance lock windows, enable backups or
change client permissions. Custom gateways still need separate adapter acceptance.
