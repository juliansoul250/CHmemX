# v0.3 decisions and evidence

[简体中文](zh-CN/v0.3.md)

The problem was practical: connecting a new client required shell adapters, and every small
addition used the full curation ceremony. v0.3 adds a narrow interface and a deliberately limited
personal mode. There is no evidence that either issue alone explains repository popularity.

| Proposal | Decision | Implementation or boundary |
|---|---|---|
| Three-tool stdio MCP | Ship | `chmemx/mcp_server.py`: start, recall, upload; tested with the official MCP client |
| Auto-merge every non-conflicting upload | Narrow | Team unchanged; opt-in personal policy for limited low-risk additions; conflicts and sensitive changes reviewed |
| Exact duplicate | Ship | Return existing ID, log event, no new candidate/commit |
| Lexical + local dense + RRF | Optional | Preserve strong lexical matches; use BM25/dense RRF when lexical retrieval abstains |
| Source signatures | Optional | Ed25519 pin, expiry, nonce replay rejection; provenance only |
| Ban instruction-like memory | Partial | Bounded string values, namespace policy and suspicious-structure quarantine; no complete natural-language grammar claim |
| Untrusted recall wrapper | Ship | Hard API data envelope and source badge; not a model sandbox or enforceable attention weight |
| Behavior/reputation | Limited | Per-source event counts and repeated-conflict review escalation; no automatic trust/privilege promotion |
| Revoke all source commits | Replace | Deactivate only current records attributed to that source; preserve later independent work and Git history |
| Incremental index + filesystem watcher | Partial | Reuse embeddings by body/model digest; recompute corpus IDF; watcher deferred to avoid races and background complexity |
| Generated evaluation cases | Retain as regression | Cannot serve as independent semantic holdout or silently relabel misses |
| Windows | Partial | Native lock branch and portable Git lookup; full Windows acceptance still pending |

## Measured retrieval results

These aggregate figures come from one private, local corpus of 90 records and 84 indexed nodes,
not a public benchmark or proof of broad generalization. No memory bodies, real query texts or
machine paths are included in this repository. Dense mode used the model pinned in
[the model lock](../examples/model-lock.minilm.json).

| Check | Frozen previous index | v0.3 candidate |
|---|---:|---:|
| Existing 136-case regression | 136/136 | 136/136 |
| Existing graph-association cases | 5/5 | 5/5 |
| 32 development paraphrases, Hit@3 | 7/32 | 24/32 |
| Separate 24-question holdout, Hit@3 | 5/24 | 19/24 |
| Unrelated queries returning no results | 22/22 | 22/22 |
| Forbidden/scope hits in checked sets | 0 | 0 |

The 24 questions were frozen before implementation. First execution scored 19/24. A later
display/ranking separation fixed two old regression rankings; the **confirmatory rerun**, no
longer blind, stayed 19/24. No held-out labels or hints were rewritten. Five holdout misses remain.
The 32 development questions were used during iteration and must not be presented as unseen proof.

Naive RRF reduced legacy Top-1 to about 83%; it was rejected. The shipped policy keeps precise
lexical results ahead of semantic fallback. This preserves regressions but can miss semantic
matches when a wrong lexical result is confident. The floor is not a calibrated probability.

On this local run, 90-record warm recall P50 was about 128 ms and P95 about 134 ms; cold encoder
initialization was about 740 ms. A one-record lexical fixture measured 28 ms for mechanical
curation to sealed review, 97 ms for commit, and 289 ms from commit to first recall. Human approval
time was not measured. Do not compare that tiny fixture's write latency with a full-corpus rebuild.
Full index metadata is still rebuilt; 174 unchanged embedding chunks can be reused by digest.

Reproduce the mechanical benchmark with:

```bash
python -m chmemx.scripts.benchmark --output /absolute/private-results/benchmark.json
```

## Security assessment

Signing answers which pinned key signed these bytes. It does not show who physically controlled
the key, whether the quoted Owner instruction is genuine, or whether the content is benign.
Unsigned local IDs remain soft identities. A registered key cannot be silently bypassed by
omitting the signature.

A natural-language ban on words such as “execute” would reject legitimate operational preferences
and still miss paraphrased malicious instructions. Instead, suspicious role/override structures
are quarantined and sensitive actions require review. This remains a heuristic. A fact-shaped
false statement can pass, especially in personal mode. The API wrapper cannot guarantee that a
consumer model will ignore malicious text; the consumer must keep it out of system instructions
and must not let recalled data authorize tools, network access or permission changes.

Source monitoring only escalates review. High acceptance rate does not grant more authority.
Evaluation distribution changes are evidence to investigate, not proof of poisoning. Full
reputation scoring, adversarial classifiers and continuous watchers remain deferred.

Source deactivation binds the current HEAD and exact affected records. Commit failure restores
only touched files. History and later replacements by independent sources survive. Git remains
local history, not an off-device backup. No automatic backup, purge or remote sync is enabled.

## Upgrade boundaries

Existing `team` stores keep exact Owner approval. The public package and Skill can be updated
without migrating or pushing real memory. The legacy scripts remain available. The MCP path uses
the v3 committed-byte reader; legacy direct CLI users should move to it to get the new read guards.
Model installation is explicit and separate. Publishing code does not select a production index.
