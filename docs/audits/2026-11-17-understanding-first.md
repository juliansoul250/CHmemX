# 理解前置修正与重新回测 · 2026-11-17

## 结论

理解前置协议已实现并验证，**不等于检索质量问题全部解决，也未部署**。

- 调用 Agent 先理解需求，普通 MCP/CLI 必须带计划；缺计划不搜索，不把分词、JSON 校验或向量编码冒充理解。
- 原问与至多三个真实子意图共享范围和读取预算，候选指针先合并去重，再读取正文。保留来源、Active、哈希和前后快照检查。
- 旧历史 162 条正例 + 10 条噪声、旧合成 43 条，字面兼容结果逐项不变。它们不能证明新理解流程有效。
- 新冻结小型合成集：候选标签通过 **8/12 提升至 9/12**；独立 Agent 只看问题生成计划，同为 **9/12**。仍有两条漏条件、一条主题相关但答不了费用问题的误命中。
- Python 3.10.1 / 3.14.6 各 **293 测试通过**；wheel、sdist、仓库外非 editable 安装及 MCP 生命周期 smoke 通过。

## 改了什么

主要代码：`src/chmemx/query_plan.py`、`src/chmemx/service.py`、`src/chmemx/mcp_server.py`、`src/chmemx/cli.py`、`scripts/retrieval_v3.py`。协议与迁移见[理解前置](../understanding-first.md)。

1. 计划明确原问、目标、search/clarify/abstain、完整实体与限定、必要子查询。拒绝未知字段、错绑原问、伪造显式片段、丢失已声明片段、超预算及重复 JSON 字段。
2. MCP recall、start 的可选召回、CLI recall、独立 v3 recall 都在 reader/模型加载前执行门禁。没有隐藏的公共入口兼容开关。
3. 范围只由原问与当前上下文确定。子查询不得引入外项目；计划模式关闭旧未知上下文的跨项目词法后备。
4. 原问和子查询在同一索引上排序指针，有界交错合并，统一加载正文和扩展关联。保留每条主结果的查询来源，不重复读取同一正文。
5. 计划查询超编码器窗口时，停止该查询的密集编码，保留完整词法查询并报告窗口超限，不静默截掉后置条件。
6. `interpretation_verified=false`、`answer_support=not_assessed` 始终明确：计划可执行不代表理解正确；候选相关不代表条件成立。
7. 独立审阅发现计划合并预截断使旧 `scan_budget_exhausted` 无法置真。已用 21 条真实合成记录、前 20 条模拟失效复现，再修正遥测：读到共享扫描上限而未填满结果且仍有未扫候选时明确报告耗尽。

类型化图谱、结构化技能意图入口未改成伪 NLP；未自动修改记忆正文、规则、主题关联或批准关系。低层 Python 和历史评估保留标明 `literal_compatibility` 的兼容路径。

## 回测隔离与防过拟合

- 沿用冻结的真实记忆、原模型、原测试标签。真实库只做隔离快照中的 **ranking-only** 回归；未访问外项目来源目录，不是当前可用性认证。
- 新 12 条用例在本轮产品代码前冻结：6 条合成记忆、11 个不同问句；两条相同歧义问句分别用于 clarify/abstain 执行契约。因此不是 12 个独立盲测问题。
- 独立解释 Agent 使用 `openai-codex/gpt-6.1-terra:high`，只提供无标签问题文件和计划协议。核对该任务工具记录：只读 PUA 规范和问题文件，写自己的计划文件；未读记忆、答案、实现或旧报告。
- 作者计划与独立计划分开执行，不把前者当理解模型证据。新问题曝光后未按错题增添关键词、别名、阈值、特例或改标签。
- 独立实现审阅使用 `openai-codex/gpt-6.1-sol:high`，只读公开代码。其静态审阅不是对回测分数的独立验证。

## 结果

### 旧字面兼容回归

真实 162 正例 + 10 噪声：前后返回集合、顺序、关联、指标及逐例判定一致；10/10 噪声空答。混合检索仍有 **6 条失败：5 条检索失败、1 条相互矛盾的关联标签**。联合门禁未通过，不能改标签或删掉关联以制造全绿。

旧合成 43 条：词法 39/43、混合 41/43，均与修正前相同；原有两条语义改写漏召回仍在。这里“不回归”仅指原字面兼容路径。

### 新理解计划试验

| 项目 | 字面查询 | 作者计划 | 独立问题解释计划 |
|---|---:|---:|---:|
| 全部候选标签通过 | 8/12 | 9/12 | 9/12 |
| 8 条正例的全部预期记录到齐 | 5/8 | 6/8 | 6/8 |
| 正例平均相关记录召回率 | 81.25% | 87.50% | 87.50% |
| 4 条无答案/歧义用例空结果 | 3/4 | 3/4 | 3/4 |
| 每请求最大正文读取数 | 2 | 2 | 2 |
| 重复正文读取次数 | 0 | 0 | 0 |

新增收益来自“谁检查、谁批准重启”的双意图检索，不是改进后所有题都能理解。

剩余新集失败：
- 带隔离密封限定的双意图问题：只找到运输规则，缺放行规则。
- 中文复合问题：只找到重新启用要求，缺冷却开门要求。
- 费用问题：找到了检查职责，却没有费用证据，仍是误命中。

这说明**理解计划、检索覆盖和答案支持是三个独立问题**。本轮实现前两者的边界与有限组合执行，没有实现答案支持核验。不能凭这个小集合宣称泛化能力已经提高；下一轮需新未见问题及独立标注，不在本集上继续追分。

## 延迟与代价
