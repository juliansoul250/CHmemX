# v0.4: reliable state, without a heavier service

[简体中文](zh-CN/v0.4.md) · [Home](../README.md)

CHmemX stays local-first: Git and files, three stdio MCP tools, optional local embeddings,
and no database daemon, automatic cloud sync or compulsory signing enrollment. Team mode
still requires direct, exact Owner confirmation. The source repository contains no real memory.

External reviews are inputs to a decision, not the product specification. We reproduced the
reported failures against v0.3.1 before changing their code paths. The decisions below distinguish
defects, inaccurate diagnoses and work intentionally left out.

## What changed

| Review finding | Decision and implementation |
|---|---|
| Unreviewed uploads omitted from backups | Confirmed. Opt-in backups now include managed uploads, queue metadata, events, nonce state and candidate/batch archives. External shared inboxes require explicitly named roots. |
| Repeated review creates batches; committed upload still Pending | Confirmed. Upload IDs and review revisions are stable, retries reuse a sealed batch, and committed Git receipts reconcile job state. |
| A commit between propose/batch/approve loses the result | Confirmed. Managed operations serialize with a cross-process lock; the core still rechecks HEAD. Interruptions retain a queryable Pending ID and structured error. This is recoverable orchestration, not one transaction spanning every file. |
| Current event causes one conflict to raise high review | Not reproduced: the threshold was three conflicts. The real defect was the current Pending event displacing an older conflict. Eligibility now uses the previous five distinct uploads; duplicate status events do not become separate observations. |
| Source validity is not checked on recall | Confirmed. Git-backed dependencies now have a derived freshness result. Changed/unavailable project facts go to `needs_review`; lessons can remain labeled historical context. No canonical record is silently rewritten. |
| Pre-signature quarantine can create unbounded files | Confirmed. Pinned sources verify before persistent queue activity. Quarantine persists counters, not bodies or individual raw events. Unsigned local mode remains supported and is not authenticated multi-user isolation. |
| Events/uploads/nonces grow without bound; stats scan every event | Confirmed. Bounded metadata replaces per-request event scans, with admission caps and backpressure. Expired nonce pruning is an explicit digest-bound CLI action. Upload/event deletion is not automated. |
| Package layout is awkward | Accepted as debt, not proof of a broken current wheel. Keep compatibility mappings; test sdist, wheel and an installed stdio lifecycle outside the checkout. Avoid a broad path migration in a reliability release. |
| Application layer uses private scope/Active methods | Replace these calls with public read interfaces. The revocation implementation still shares internal rollback helpers; that smaller seam remains debt. |
| One taxonomy cell per project | Improve the default to scoped key-parent topics. Keep record vectors separate. This is a starter directory, not automatic discovery of a rich knowledge graph. Curated node relationships remain the authority. |
| Missing lint, Python 3.10 and Windows CI | Add lint and Linux 3.10/3.12, macOS 3.11, Windows 3.11 jobs, including installed-wheel smoke. Check actual workflow results; a matrix declaration alone is not a pass. |
| Chinese-only confirmation / production fault-injection argument | Add exact English confirmation alongside Chinese; remove the test-only production parameter. Tests simulate a real failed write instead. |
| Regex risk rules cannot guarantee injection safety | Agree with the limitation, reject the implication that another blacklist solves it. Keep layered provenance, review, untrusted-data envelopes, isolation and revocation. The consumer still must enforce tool authorization. |

## Stable uploads and reviews

Add a source-owned `request_id` to `upload`. A retry with the same content returns the same job;
reusing that ID for different content fails `IDEMPOTENCY_CONFLICT`. Without an explicit ID,
exact payload retries are content-addressed. When intentionally resubmitting after source changes,
use a new request ID. Signed requests bind `request_id` when present. A repeated signature/nonce
still fails replay protection: query the existing job with `start(upload_id=...)`, or sign a new nonce.

`review UPLOAD_ID` reuses its current sealed review. `review UPLOAD_ID --refresh` retires the previous
review and creates a new revision; its old confirmation can no longer approve it. A changed source
may need a new upload rather than a refresh. Successful commit recovery uses Git, not a claimed job
status. Status reconciliation includes `checked_head` and `active_record_ids`; later deactivation
returns `COMMITTED_NOT_ACTIVE`, and a reverted approval returns `COMMIT_NOT_CURRENT`. Neither is
automatically resubmitted. Use recall for the current Active view. Queue recovery after an I/O failure may require disk repair;
it is not a guarantee against hardware loss.

MCP errors retain `code`, `message`, `details`, and `retryable`. An admitted personal-mode upload
interrupted by HEAD drift returns `PENDING_CURATION` plus `upload_id` and its phase error. If the
queue cannot persist at all, the server reports failure and does not promise a durable receipt.

## Bounded queue and maintenance

Default caps: 10,000 managed uploads, 1,000 raw event files, 256 source identities, 10,000
nonce entries, 120 requests/source/minute, and 16 refresh revisions/upload. Operators can change
`queue_limits` in their Git-controlled policy. These are count bounds for this interface, not disk
quotas on arbitrary same-user filesystem writes or legacy bulk commands. Bodies remain bounded
by the upload API. Raw-event overflow becomes aggregate counts; it is not a complete event history.

Source statistics read bounded `state.json`, not thousands of event JSON files. This avoids
per-event file opens but still parses the metadata document; it is not constant-time at arbitrary
queue size. Legacy state gets a one-time bounded inventory; oversized legacy queues stop for
operator migration. Pending contents are never discarded to make room.

```bash
chmemx --store /absolute/private-memory maintenance-plan
chmemx --store /absolute/private-memory maintenance-nonces --digest EXACT_PLAN_DIGEST
```

The second command is an explicit operator decision. It only removes replay entries whose signed
expiry plus a five-minute margin has passed. A changed queue or eligible set invalidates the plan.
It does not delete upload/event files, legacy nonce marker files or Git history. Full terminal-job
archive/purge is intentionally not implemented in this release. Capacity errors ask for maintenance,
not silent eviction. No maintenance command runs on startup or a timer.

## Source freshness and fact identity

Freshness and approval are separate. A file hash match means the bound source bytes still match,
not that a statement is true or that a test was rerun. State/evidence records are revision-bound;
an unrelated project commit does not stale an unchanged decision/contract, but does require fresh
evidence before reusing an old version's test/progress result as current.

`needs_review` is not a new Active channel. All results remain untrusted historical data. Private
Agent directories and symlink sources are not followed. Offline/missing sources return unknown,
not a fabricated current result. Automatic parsing of free-text expiry rules, multi-file/symbol
dependencies and runtime test re-execution remain out of scope. Candidate ranking comparisons can
explicitly disable source checks for a frozen snapshot, but mark it `NOT_CHECKED_SNAPSHOT`; public
MCP/CLI recall has no source-check bypass option.

`start(key_query="...")` offers a fact-key directory derived from scoped Active records, optionally
extended by a curator's Git-controlled `fact-key-catalog.json`. Each definition contains `key`,
`scope`, `project_id`, `allowed_classes`, `aliases`, and `description`. Declared aliases trigger a
review suggestion, never an automatic merge. This does not solve all differently named duplicates.

Personal mode now auto-saves only low-risk new preferences from configured sources. Other classes,
even if named `fact.*`, need review: a prefix and a source reference do not prove a factual assertion.
Team mode and existing snapshot/sync settings do not change on upgrade.

## Backup and restore

Backups remain opt-in; this release does not turn them on. A Git commit is not a backup of Pending.
External inboxes are separate deployments and are not discovered by scanning tool-private folders.

```bash
chmemx --store /absolute/private-memory backup --output-root /absolute/backups \
  --pending-root shared=/absolute/shared-inbox
chmemx restore-backup --directory /absolute/backups/BACKUP_ID --destination /absolute/new-restored-store
```

Backup manifests state coverage and bind file bytes. Restore requires a new destination, restores
managed queue state and stages external roots under `.queue/restored-external/`. It never overwrites
a live external inbox. Source-project roots are not silently redirected on another machine. Test
restoration and explicitly rebind projects before current-source recall. A private team gateway
with its own inbox/receipt layout needs its own integration check; updating the public wheel alone
does not upgrade that gateway's contracts.

## Evidence and remaining gates

Run `python -B -m unittest discover -s tests -p '*test*.py'`, `ruff check --config pyproject.toml .`,
`python -m build`, and `python tests/installed_package_smoke.py`. Fixtures are synthetic. Tests cover
cross-process retries, phase interleaving, old-review rejection, signature admission, quotas,
explicit nonce maintenance, backup/restore, aliases, freshness and isolated MCP lifecycle.

No model weights, thresholds, golden answers or held-out query hints were tuned for this release.
Ranking regression and current-source validation are reported separately. Real desktop-client
compatibility still needs per-client evidence; an SDK or subprocess test does not prove every UI.

Local release observations (macOS, Python 3.10, synthetic lifecycle): lint and the release suite pass;
the sdist-built wheel completes an isolated installed MCP/CLI lifecycle. Frozen ranking retains
136/136 regression cases, 174/174 generated coverage, 5/5 associations and 22/22 abstentions.
The previously frozen 24-question set remains 19/24, with five unresolved misses; this repeat is
not new blind evidence. Source-check eligibility is tested separately, not disabled in public recall.

Two one-preference mechanical runs took 0.54–0.61 seconds from upload to recall (prior v0.3.1
observation: 0.36 seconds); warm recall P95 was 118 ms (prior: 97 ms). Durable checkpoints have a
cost, and these small sequential observations are not a controlled throughput claim. Human review
time was not measured. Multi-project source-check latency and large-queue operation need their
own measurements before promising wider performance gains.

The first Windows run found native path separators in Git object references, locale-dependent JSON
reads and a pre-lock read racing another process. These are fixed in code, not skipped in tests.
The Windows lock uses the [documented byte-range behavior](https://docs.python.org/3/library/msvcrt.html#msvcrt.locking)
without reading a byte another process may own. UTF-8 JSON and Chinese text are exercised by the
installed-package lifecycle. Same-user filesystem access still is not an authentication boundary.
