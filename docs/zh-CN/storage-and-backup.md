# 本地存储、迁移与备份

[文档目录](README.md)

## 两个 Git 仓库

CHmemX 工具仓库与真实记忆仓库必须分开：

| 路径角色 | 保存内容 | 是否适合公开 |
|---|---|---:|
| `MEMORY_GRAPH_KIT` | 工具代码、Skill、Schema、文档、合成测试 | 是 |
| `MEMORY_GRAPH_HOME` | Active Memory、项目绑定、审批证据和 Git 历史 | 否 |

推送 CHmemX 只会发布工具代码。它不会自动上传 `MEMORY_GRAPH_HOME`。

各工具的 `inbox/` 是待整理中转区，也不应进入公开仓库。

## 本地 Git 能解决什么

Git 可以查看提交历史、比较版本、追踪 Supersede，并通过新 Revert 提交恢复误写。它适合处理逻辑错误和错误审批。

Git 仓库仍然保存在同一块硬盘上。硬盘损坏、误格式化或整机丢失时，本地 Git 可能与工作文件一起消失。

## 外部备份

硬盘损坏保护需要另外配置外部副本，例如：

- 另一块物理硬盘；
- 私有 Git 远程仓库；
- 受访问控制的云盘目录；
- 经 Owner 明确启用并验证的 CHmemX Snapshot 策略。

外部备份是否加密取决于数据敏感度和使用环境。无论是否加密，记忆仓库都不得保存密码、Token、Cookie 或私钥。

备份完成不等于可恢复。至少应验证 Git 对象、HEAD、分支和关键 Active Index 可以读取，并定期在临时目录进行恢复演练。

## 迁移到另一台电脑

保守迁移流程：

1. 在新电脑安装 Python、Git 和 CHmemX 工具仓库。
2. 把完整 `MEMORY_GRAPH_HOME` Git 仓库恢复到受保护的本地路径。
3. 检查 `git fsck`、`git status` 和 `simple_memory.py status`。
4. 恢复正式项目仓库，并核对 Memory Graph 中保存的项目根路径。
5. 如果新电脑的绝对项目路径不同，先在副本中规划绑定迁移。当前 Runtime 没有自动重写项目根路径的命令。
6. 使用正式内容分类文件重建向量索引，不依赖旧电脑留下的派生索引。
7. 用几个已知主题验证全局、项目和跨项目召回。

迁移期间不要同时在两台电脑上写入同一个真实记忆仓库。CHmemX 当前不是多主同步系统。

## 公开仓库不是备份

`https://github.com/juliansoul250/CHmemX` 只用于分发工具。公开仓库中的示例是虚构数据，不能恢复你的真实 Active Memory。

如果没有单独配置外部备份，真实记忆仍是纯本地状态。
