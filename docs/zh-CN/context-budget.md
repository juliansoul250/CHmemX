# 限量召回，不再增加一个记忆库

本页描述尚未发布、尚未部署的开发工作树改动。

CHmemX管理经过审阅的长期记忆。日志、网页和命令输出属于当前任务的临时证据，
应留在所属项目内，不因有检索价值就写入Active，也不为收集这些数据扫描其他会话。

## 两项改动

1. v3召回先使用索引元数据计算词法分数，再读取有界的主结果及关联候选正文。
   记录哈希、Active身份、来源有效性、查询前后HEAD校验保持不变；评分与图谱规则不变。
2. 现有`recall`增加可选`body_limit`，范围256—16384个字符。省略时仍返回完整正文，
   不改变旧调用；不新增MCP工具、数据库、后台进程或执行权限。

```json
{"query":"编辑器偏好","limit":3,"body_limit":1024,"association_limit":0}
```

CLI可使用`recall '编辑器偏好' --limit 3 --body-limit 1024 --association-limit 0`，
其余store/cwd参数沿用原配置。`association_limit`开放原检索器已有的关联预算，范围0—8，
默认仍为3；只需主结果时明确选0，不代表关联排序问题已经修复，更不能用它重写旧回测条件。

每条预览附`body_preview`：原文字符数、返回字符数、是否截断、完整UTF-8正文的SHA-256。
来源、作用域、来源徽标、时效性和排名信息保留。限制的是正文字符数，不是整个响应字节数，
更不是模型实际计费Token。

**截断预览不能代替完整证据。** 否定、例外和条件可能在末尾。需要依赖内容时，省略
`body_limit`重读，可用精确Canonical Key缩小范围；确认记录ID和完整正文SHA-256一致。
身份或内容已变则重新核验。批准批次仍走原完整review与diff，不能根据预览批准。

## 接入边界

吸收context-mode“证据留在本地、按需读取”的方法，不复制其实现，不安装全局Hook，
不覆盖AGENTS.md，不自动回填历史，不改变模型、正式索引、Active和Owner确认规则。
现有知识图谱仍是隔离试点，图中关系不代表执行权限。

回测固定索引和题集摘要，分别比较正文I/O、输出大小、时间、命中、弃答、禁止命中和图谱关联。
合成样本只能说明机械回归，不能包装成独立语义准确率或真实账单节省。旧来源失效仍须由来源方
核验，不能为通过回测而放宽门禁或重写金标。

评测报告新增`diagnostics`，不改变原指标与通过条件。主结果逐题分为：要求名次内命中、
全部期望被来源阻断、扫描预算耗尽而未解决、部分来源阻断而未解决、原因未解释的漏召回。
这是观测分类，不是根因判定。主结果命中仍可能因禁止关联或越界而整题失败。

`positive_association_coverage: ABSENT`表示题集没有预期关联的正向用例，不是图谱质量通过。
独立添加正向及排除用例不能替代冻结题集，也不能把来源门的安全弃答算成检索命中。
