# 可选的约束式Skill检索

本模块从明确提供、已审阅的能力目录中推荐Skill。它不修改记忆recall，不增加MCP工具，
不安装Skill、不读其他Agent历史，也不替换Codex原生选择机制。

## 先理解，再检索

由当前Agent根据请求和上下文，先提取正向目标、禁止动作、项目与阶段，形成结构化输入。
模块不声称能自行解析任意自然语言，不能靠删除“不要”或“UI”等词来处理否定。

- “只审查UI，不生成UI”：需要UI审查能力，允许读取，禁止生成图片。
- “只改按钮，不重做整屏”：允许局部编辑，禁止整图生成。
- “查股票，不生成UI”：只把股票读取能力放入候选范围。
- 双重否定、引用和冲突指令要结合上下文理解；无法确定时用`decision: clarify`。
  无需专项Skill时用`decision: abstain`；“继续”要沿用真实任务上下文。

模块在编码描述前过滤能力、动作、项目和阶段，排序后再次检查同一份不可变元数据。
没有合格候选、没有正相似度或意图未明确时，不强行选一个最接近的Skill。

## 使用

在已安装CHmemX的源码目录运行合成示例：

```bash
python -m chmemx.skill_retrieval \
  --catalog examples/skill-catalog.json --intent examples/skill-intent.json
```

示例只返回`ui-review`：生成候选被禁止动作排除，另一个项目的候选被项目范围排除。
默认是本地词法余弦检索，不需要记忆库或可选依赖。安装`semantic`额外依赖且已有经哈希
校验的本地模型时，可加`--model-dir /absolute/verified-model`。模块不会下载模型；被排除
的描述不进入编码器，候选为空时也不加载模型。当前ONNX编码器按模型token上限截断输入，
可能影响排序，但不会截断独立检查的约束元数据。

Python入口为`chmemx.skill_retrieval.recommend(catalog, intent, limit=5, encoder=None)`。
自定义编码器应返回等维、有限数值的向量列表，且数据处理方式须已获准。

## 约束

目录项需有唯一`id`、`description`、非空`capabilities`和`actions`，可选`projects`与`stages`
为非空白名单。未声明范围只表示目录内不限制，不意味着获得所有项目权限；缺少调用上下文
不能命中受限项目或阶段。搜索输入需有`decision: search`、正向`query`、能力标签、允许与
禁止动作列表；禁止列表可以为空。能力至少交集一项，动作则必须全部获准且没有任何被禁项。
标签使用NFKC和大小写归一后的精确比较，不自动猜同义词。

读写混合Skill不能在只读请求里被偷偷“部分启用”。确实有独立模式时，分成经过审阅的目录项。
最多1000项目录、每组32标签、每标签64字符、描述4096字符、查询2048字符、文件8MiB，返回1–20项。
未知字段、重复标签或JSON字段、非法向量等会拒绝。

结果包含候选ID、分数、动作、约束检查及排除理由；不输出指令正文，并始终返回
`execution_authorized: false`。状态包括`CANDIDATES`、`NO_MATCH`、`ABSTAIN`、
`NEEDS_CLARIFICATION`和统一CLI错误结构。

分数不是正确率或授权。意图解析错误、目录虚报能力，仍可能导致错误推荐；当前Agent负责
正确解释请求、核查目录和执行前的权限判断。这不是沙箱，也不是完整的提示注入防御。

回归测试只证明结构化约束管线，包括检查哪些描述真的进入编码器；不证明自然语言解析准确率，
也不证明原生Codex选择准确率。此模块尚需在调用方工作流中单独验收。不要将动作过滤搬进
记忆检索，否则查找“禁止生成UI”的规则时可能把需要的记忆排除。
