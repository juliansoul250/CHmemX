# v0.5.2 更新说明

[English](../v0.5.2.md) · [返回主页](../../README.zh-CN.md)

本次修复注册失败回滚、跨项目审阅副作用、来源文件换行比较，以及上传正文丢失后的对账。写入政策和检索排序不变。

## 注册与审阅

项目注册、来源公钥注册统一使用正式事务边界。操作失败且 HEAD 未变化时，只恢复本次声明的文件和暂存区条目。新建的项目目录仅在为空时移除，不动无关文件；如果目录内出现其他文件，保留它们并返回 `ROLLBACK_DIRECTORY_REMAINS`，列出待检查路径。预先存在的项目目录不会被接管。提交已经成功、但命令响应中断时，也不会误撤销该提交。

审阅会先核对上传包所属项目，再同步任务状态或作废旧批次。从其他项目执行 `review` 或 `--refresh`，返回 `UPLOAD_CONTEXT_MISMATCH`，原有确认仍有效。全局上传不受项目切换限制。

## 来源有效性

来源的 Git 提交字节仍一致时，v3 可以识别 Git 声明的 CRLF/LF 文本转换。检查会对比已提交与工作区的属性，并读取 Git 的文本分类，不运行 clean、smudge 等内容过滤器。实际内容变化仍被判为过期；二进制以及需要 filter、`ident`、`working-tree-encoding` 的转换不享受这个例外。进度与测试证据仍绑定原项目版本。

比较依据是 [Git 的文本与换行属性](https://git-scm.com/docs/gitattributes)。此例外要求 Git 支持 `check-attr --source`；属性不可核验时不放行。检查不改文件、属性或 Git 配置。原始字节完全一致的情况继续按原规则处理。

## 上传正文丢失

显式执行 `maintenance-plan --action reconcile` 时，对账复用状态查询和审阅使用的有界 Git 历史证明。若热上传文件丢失，但当前祖先历史能证明该审批已被回滚，回执保留 `COMMIT_NOT_CURRENT`，并校验对应的上传 ID。

`payload_available=false` 表示正文仍然缺失。找回生命周期证明不等于恢复正文，也不会重新激活记忆。找不到证明时，仍返回 `UPLOAD_DATA_MISSING`。

## 升级与保留边界

安装固定版本后重启 stdio 进程。现有政策、记忆和索引不变。旧版本遗留的脏仓库不会自动修复；恢复前必须检查注册差异及 HEAD，不能整仓还原。未执行的维护计划需重新生成。

README 补充 Team/Personal 对比，并区分当前 v3 检索和旧 `vector_memory.py` 词法指向器。旧命令与格式继续兼容。本次不调向量参数、不增加模型、不缩短维护持锁窗口、不启用备份，也不更改客户端权限。自定义网关仍需单独验收适配。
