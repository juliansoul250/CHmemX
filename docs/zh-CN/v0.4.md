# v0.4：补齐可靠性，保持轻量

[English](../v0.4.md) · [首页](../../README.zh-CN.md)

这次修的是待审内容丢失、重试状态不一致和旧来源误用，不增加数据库服务、后台监听器或强制签名注册。仍然是本地文件与 Git、三个 stdio MCP 工具、可选本地向量模型。团队模式继续由 Owner 精确确认；公开仓库不包含真实记忆。

## 外部评审如何处理

确认并修复：未审阅上传漏进备份；重复 review 新建批次；提交后上传仍显示 Pending；阶段间插入提交后缺少结构化状态；原项目变化后旧正文仍直接返回；验签前写隔离事件；逐次扫描全部事件。

两项判断需要纠正：

- 单次冲突不会直接升为高审查，原阈值是最近五项内三次冲突。实际问题是当前 Pending 把较早冲突挤出窗口，可能提前降级。现在先看之前五次独立上传，同一上传的状态更新不当成新样本。
- 检索并非全靠 BM25/RRF。现有高置信词法路径仍优先，融合排序负责后备；图谱关联另行返回。本轮不改权重，不针对外部给出的例题调金标。

打包目录映射确实不够直观，但不能因此断言当前 wheel 已坏。这轮保留兼容路径，补 sdist、wheel 和仓库外安装测试。自动网格改按项目和键的主题父级分组，仍不把这种基础目录称为自动知识建图。

## 已实现

- `upload` 支持 `request_id`。相同请求重试复用上传；同 ID 换内容拒绝。`start` 可查询上传状态。重复 review 复用密封批次，显式刷新会使旧确认失效，提交结果可从 Git 回执恢复。
- 各阶段仍校验 HEAD。被并发提交打断时，已接收内容保持 Pending，并返回上传编号与错误码。不是把全部文件伪装成一个跨阶段事务。
- 注册过公钥的来源先验签，再写队列状态。隔离只计数，不落正文和逐条原始事件。未签名本地模式仍存在，不宣称多用户鉴权或操作系统隔离。
- 统计读取有界元数据，不再逐个打开全部事件文件。默认限额为：上传 10,000、原始事件 1,000、来源 256、nonce 10,000、每来源每分钟请求 120、每上传刷新 16 次。达到限额保留待审内容并拒收，不静默清空。
- `maintenance-plan` 展示状态；只有显式执行 `maintenance-nonces --digest 精确摘要` 才移除过期超过五分钟的防重放条目。队列变化就拒绝旧计划。没有自动定时清理，也没有上传、事件和历史文件的自动删除器。
- 备份纳入托管上传、元数据、事件、防重放状态及候选/批次。共享外部 inbox 必须通过 `--pending-root 标签=绝对路径` 声明。恢复只写新目录，外部 inbox 先放到 `.queue/restored-external/`，不覆盖现有目录。
- `recall` 区分审批状态与来源时效。项目文件变化或不可用时，事实类结果进入 `needs_review`；经验可保留为有标签的历史上下文。不直接改 Active，不把“文件未变”当成“结论正确”或“测试重跑”。
- `start(key_query=...)` 提供事实键目录。可声明别名和允许的 class，但只提示人工对比，不自动合并同义键。个人模式自动保存限于低风险偏好，不能把任意事实标成 `fact.*` 就自动通过。
- 精确确认支持中文和英文；生产函数不再暴露测试故障注入参数。CI 增加 lint、Linux Python 3.10/3.12、macOS 3.11、Windows 3.11 与安装后的 MCP 流程测试。

参数、状态及测试命令见[完整说明](../v0.4.md)。CI 的实际结果以对应提交的工作流为准，不以“写了矩阵”代替通过。

## 保留的边界

签名只能证明私钥持有者，不能证明诚实。风险正则和“历史数据而非指令”的包装也不是模型沙箱。记忆不得自行赋予执行命令、读取文件或修改权限的权利，消费它的 Agent 仍要遵守当前授权。

来源时效只核对绑定的文件和版本，不自动理解自由文本里的过期规则，也不重跑项目测试。未解析的多文件依赖、完整终态队列清理、密钥轮换和每个桌面客户端的行为验收仍在 backlog。元数据读取不是任意规模下的 O(1)，限额也不能限制同一用户绕过接口写文件。

快照和同步仍默认关闭，升级不会自动打开。自定义团队网关可能有独立的上传目录和回执协议；公开包更新不代表那套网关已完成升级。真实记忆与当前向量索引不随这次源码发布替换。

## 本机验证

lint、92 项测试及独立环境安装后的 MCP/CLI 流程通过。冻结排序复测保留原有 136/136、生成覆盖 174/174、关联 5/5 和无关查询 22/22；24 项保留题仍是 19/24，五个漏召回继续保留，不改答案。这是重复回归，不是新的盲测。来源时效另测，正式 recall 没有关闭检查的参数。

单条虚构偏好的机器流程两次测得 0.54～0.61 秒，旧版一次记录为 0.36 秒；热召回 P95 约 118ms，旧记录约 97ms。持久化检查点有成本，不把可靠性改进包装成全面提速。这组小样本也不能代表大队列和多项目来源检查；人工审阅耗时尚未测量。
