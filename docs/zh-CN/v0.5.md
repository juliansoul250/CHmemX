# v0.5 版本说明

[English](../v0.5.md) · [首页](../../README.zh-CN.md)

v0.5 补齐请求身份、证据更新、恢复和队列维护。日常 MCP 仍只有 `start`、`recall`、`upload`，管理操作留在 CLI。

## 上传与重试

新请求身份绑定来源 Agent、Scope 和注册项目 ID。同一项目的子目录共用身份，全局偏好仍是全局范围。即使上传只得到“精确重复”，显式 request_id 也会保存最小回执；换内容复用这个编号会被拒绝。重复回执不占工作队列名额，也不创建 Active 提交。

可核验的 v0.4 请求继续使用原编号，不改旧批次。旧版没有记录的无操作请求无法凭空恢复；来源不明的缺失输入需要恢复原件，或换一个明确的新请求编号。

正文相同，证据版本仍可能不同。证据、状态或项目合同的有效来源变化时，可以形成带来源差异的 Pending 替代项，仍须审阅和确认。稳定偏好不因此反复提交。

事实键目录损坏时，新候选进入 `FACT_CATALOG_REVIEW_REQUIRED` 待审状态；修好并提交目录后才能封批。正式存储损坏仍拒绝处理。CLI 与 MCP 使用相同错误字段，缺失来源有明确错误码。抽样不再受 request_id 影响；签名仍绑定它，已验证请求即使被隔离也会使用 nonce，回执会明确说明。

## 查询与恢复

查询在最终选取结果时检查来源有效性，并从已通过相关性门槛的候选中有界补位。待复核条目另计预算，关联从可用主结果展开。达到扫描预算会明确报告，不降低相关性门槛来凑数量。同一次请求可复用来源检查，跨请求不缓存其有效性。

恢复会在检出文件前设置应用所需的仓库本地 Git 身份和换行配置，不改全局 Git 设置。换电脑后仍要核实项目路径绑定。验收覆盖恢复后审阅、新提交和再次召回。

## 队列维护

详见[维护指南](maintenance.md)。归档释放工作队列名额并保留历史；清理压缩历史后仍留最小请求回执。回执过期是另一项明确操作，至少保留 180 天，执行后旧编号可能被作为新请求处理。没有自动过期或自动删除。

维护计划绑定仓库、HEAD、文件清单及前后字节哈希，显示空间估算，24 小时内有效，执行须匹配精确摘要。准备或执行中断后，队列写入暂停，直到明确完成或回滚恢复。发现外部改动时停止，不覆盖它。

正式 Active、审批历史、项目文件和外部 inbox 都不是清理目标。可选备份覆盖队列归档、回执和已完成的维护记录；有未解决事务时拒绝备份。恢复日志处理进程中断，不代替硬盘损坏时所需的独立备份。

## 升级边界

更新工具环境后重启 stdio 进程即可使用新入口。升级不改 Active 结构，不自动清理，不打开快照、全局 Hook 或云同步。自定义网关若使用不同上传协议，仍须单独验收。

测试使用虚构数据。跨平台 CI、安装包测试、冻结排序回归和真实客户端使用是不同验收项。本版不修改模型权重或保留题答案；历史教训仍是参考数据，不是当前指令或授权。
