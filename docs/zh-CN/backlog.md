# Backlog 优先级

[English](../../BACKLOG.md) · [中文主页](../../README.zh-CN.md)

Owner 于 2026-09-06 指定的顺序：

1. MCP server
2. 分级确认
3. 签名／行为指纹／召回隔离
4. 混合召回
5. 增量索引

这是剩余工作的排期。保留 v0.3.1 已有实现，不回退重做；先补齐最靠前的未验收项，
再扩展后续能力。基线测量贯穿每阶段，局部实现不等于整个阶段完成。

## 1. MCP server

- [x] 已有 start、recall、upload，CLI 安装包、普通安装修复和官方 SDK 联调测试。
- [ ] 分别完成真实 Codex、ZCode、Claude Code 客户端验收，记录版本、配置、返回值和未通过项。
- [ ] 验证启动失败、重连和返回内容上限，保持日常接口简单。

验收标准：新环境按文档安装后，能完成加载上下文、带来源上传和范围化召回。
Pending/Active 状态准确，不依赖其他工具的私有目录。

## 2. 分级确认

- [x] 默认团队审批；可选受限单人模式；精确重复不写入；冲突审查和政策授权回执。
- [ ] 补齐政策预览、待审与重试回执一致性、并发及幂等流程。
- [ ] 分开记录确认次数、机器耗时与人工等待时间。

验收标准：政策允许的新增项操作简短，重复不重复写入；冲突、敏感项和抽审项仍需审查。
已有团队仓库不能静默放宽，政策变更必须获得 Owner 明确授权。

## 3. 签名／行为指纹／召回隔离

- [x] 已有可选 Ed25519 固定来源、重放拒绝、冲突计数升级审查、历史数据包装和按来源停用。
- [ ] 补齐公钥轮换、撤销和可归因审计。
- [ ] 增加有界的来源／Canonical Key 行为窗口，显示异常冲突、撤销等信号及审查理由。
- [ ] 真实验证各客户端的消费行为：不能让记忆授权工具执行、提升权限或成为高优先级指令。

验收标准：伪造、重放和已撤销输入按合同拒绝；异常提高审查等级；隔离内容永不召回；
来源停用保留其他来源后续确认的修正。签名只溯源，包装不是沙箱，声誉不增加权限。
消费端未实测前，本阶段仍是部分完成。

## 4. 混合召回

- [x] 已有可选本地 ONNX 语义后端、词法优先的补召回和一跳主题关联。
- [ ] 用独立冻结评测处理“词法高分但选错”的情况，不给失败问题定向补提示词。
- [ ] 扩展换说法、拒答、范围隔离和召回分布对照；用过的调参集不再冒充盲测。

验收标准：固定回归、范围与负例通过，独立保留集改善，时延及内存开销达标。
候选通过发布门禁前保留旧索引；平均提升不能说成每条查询都正确。

## 5. 增量索引

- [x] 已有正文／模型摘要相同的嵌入复用，全局 IDF 仍明确重算。
- [ ] 补齐记录、节点、内容网格的增量更新，以及 generation 一致性、原子发布和故障恢复测试。
- [ ] 对比完整重建，证明“写入到可召回”的整体时延改善，不只统计少算了多少嵌入。
- [ ] 增量正确性通过且确有需求后，再考虑可选文件监听。

验收标准：同一组变更的增量结果与全量重建等价；中断及并发更新不能暴露混合版本。
嵌入缓存复用不等于完整增量索引。

当前发布状态见 [v0.3 评估](v0.3.md)、[MCP 使用](mcp.md)和[检索验收](../semantic.md)。
